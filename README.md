# Crypto WatchBot — نسخهٔ آزمایشی ۰٫۴

ربات پژوهشی شخصی برای SOLUSDT، ORDIUSDT، LINKUSDT و BTCUSDT: تحلیل روزانه/۴ساعته/۵دقیقه، تصویر دقیق چارت، پیام فارسی تلگرام، ثبت وضعیت و شبیه‌سازی معاملات. این پروژه **هیچ مسیر ثبت سفارش واقعی، کلید صرافی، برداشت یا تغییر اهرم ندارد**.

کد قابل اجراست؛ سودآوری قواعد اثبات نشده و اجرای شبانه‌روزی آن به کامپیوتر روشن یا میزبان نیاز دارد. GitHub محل کد و CI است. هزینهٔ میزبانی و احتمال محدودیت شبکه به محیط اجرا بستگی دارد.

نسخهٔ ۰٫۴ بک‌تست محدود روی آرشیو دارای checksum بایننس، فیلترهای اختیاری، خروج پله‌ای، ساعت مجاز ورود و نمایش مستقل قیمت زنده دارد. [راهنمای پژوهش و فعال‌سازی](RESEARCH_AND_LIVE_FA.md). پروفایل اصلی حفظ شده و KX جایگزین نشده است.

داشبورد فارسی شواهد، چارت تعاملی، بازپخش تصمیم‌ها، کنترل محلی و پرسش از ژورنال اضافه شده است. [راهنمای کامل داشبورد](DASHBOARD_FA.md):

```bash
python -m watchbot dashboard
python -m watchbot dashboard-export --output runtime/dashboard-snapshot.json
```

خروجی `runtime/demo/` شامل CSVهای ساختگی، چهار چارت PNG، متن پیام و JSON تحلیل است. برچسب **SYNTHETIC_DEMO_NOT_MARKET_DATA** روی تصویر و گزارش درج می‌شود. دمو نه به تلگرام چیزی می‌فرستد، نه سابقهٔ سودآوری تولید می‌کند. برای اجرای مجدد مستقل، `demo --output runtime/demo-2` بزنید.

## بررسی آمادگی اجرا

```bash
python -m watchbot doctor
python -m watchbot doctor --live
```

فرمان اول تنظیمات، وابستگی‌ها، منطقهٔ زمانی تهران، وجود تنظیمات تلگرام و وضعیت بازبینی خبر را بررسی می‌کند. فرمان دوم علاوه بر این، دسترسی عمومی به منبع داده، فعال‌بودن تمام نمادها و کامل‌بودن کندل‌های بسته‌شدهٔ هر سه تایم‌فریم را می‌سنجد. هیچ‌یک پیام تلگرام ارسال نمی‌کند، فرمان ربات را مصرف نمی‌کند یا دیتابیس معاملات را ایجاد نمی‌کند.

خروجی JSON دارای `PASS`، `WARN` و `FAIL` است؛ کد خروج ۱ یعنی حداقل یک خطای مسدودکننده وجود دارد. مقدار `ok: true` فقط به معنی نبود خطا در بررسی‌های انجام‌شده است. برای تأیید دادهٔ زنده باید `market_verified: true` باشد؛ وجود توکن تلگرام، تحویل پیام را تأیید نمی‌کند. خبر نامشخص نیز به شکل هشدار نمایش داده می‌شود و همچنان ورود فرضی را مسدود می‌کند. در ویندوز، بستهٔ `tzdata` همراه نصب وابستگی‌ها نصب می‌شود.

راهنمای وضعیت فعلی و ادامهٔ کار از گوشی در [GETTING_STARTED_FA.md](GETTING_STARTED_FA.md) آمده است.

## پایش دادهٔ عمومی

```bash
python -m watchbot once
python -m watchbot run
```

- منبع نسخهٔ اول `binance-usdm-reference` است: کندل قیمت معاملات قرارداد دائمی USDT در Binance؛ **دادهٔ KCEX یا Mark Price نیست**. معرفی منبع داده به معنی پیشنهاد افتتاح حساب در آن نیست.
- API عمومی بدون کلید صرافی استفاده می‌شود؛ اگر دسترسی از محیط شما مجاز/ممکن نیست، از CSVهای منبع مجاز استفاده کنید. هیچ پراکسی یا روش دورزدن محدودیت در پروژه وجود ندارد.
- ابتدا وجود نماد و قرارداد دائمی فعال بررسی می‌شود. نماد ناموجود باعث توقف روشن می‌شود؛ نام نماد مشابه بی‌اطلاع جایگزین نمی‌شود.
- WebSocket فقط بسته‌شدن کندل ۵دقیقه را اعلام می‌کند؛ دادهٔ نهایی از REST دریافت و اعتبارسنجی می‌شود. هر ۱۵ ثانیه نیز بررسی پشتیبان انجام می‌شود. تأخیر صفر تضمین نمی‌شود.
- بسته‌شدن کندل، UTC، ترتیب، OHLCV، نبود دادهٔ تکراری و گپ و تازه‌بودن داده بررسی می‌شود. اختلاف ساعت میزبان بیش از ۱۰ ثانیه باعث توقف اسکن می‌شود.
- بعد از قطع اتصال، کندل‌های ازدست‌رفته در محدودهٔ تاریخچه بازیابی می‌شوند؛ اگر فاصله بیشتر از تاریخچهٔ موجود باشد، شبیه‌سازی متوقف می‌شود تا سابقهٔ کامل بازیابی یا آزمایش جدید آغاز شود.
- در `runtime/heartbeat.json` زمان آخرین اسکن موفق ثبت می‌شود. عدم به‌روزشدن این فایل را باید میزبان بیرونی پایش کند؛ برنامه برای پیام‌دادن هنگام قطع کامل اینترنت تضمینی ندارد.
- قبل از پردازش، تمام نمادها و تایم‌فریم‌ها در زمان نهایی دریافت دوباره اعتبارسنجی می‌شوند؛ عبور زمان از مرز کندل هنگام دریافت داده، اسکن ناقص را موفق ثبت نمی‌کند. فایل heartbeat به‌صورت اتمی جایگزین می‌شود و زمان snapshot و نام منبع را هم دارد.

## تلگرام

۱. با [BotFather](https://t.me/BotFather) ربات بسازید و در گفت‌وگوی خصوصی ربات `/start` بفرستید.

۲. توکن را فقط در متغیر محیطی یا Secrets میزبان بگذارید. `TELEGRAM_CHAT_ID` باید شناسهٔ مقصد متعلق به خودتان باشد؛ برای یافتن آن از روش‌های رسمی Bot API استفاده کنید. توکن را در GitHub، چت عمومی، URL مرورگر یا اسکرین‌شات قرار ندهید.

```bash
# مقادیر نمونه‌اند؛ توکن واقعی را در secret manager میزبان تنظیم کنید.
export TELEGRAM_BOT_TOKEN='YOUR_PRIVATE_TOKEN'
export TELEGRAM_CHAT_ID='YOUR_PRIVATE_CHAT_ID'
python -m watchbot run
```

متغیرهای `.env` در اجرای مستقیم Python خودکار بارگذاری نمی‌شوند؛ در شل تنظیمشان کنید. Docker Compose فایل `.env` را می‌خواند. بدون این دو متغیر، تحلیل محلی انجام می‌شود و ارسال غیرفعال می‌ماند.

- `/status` و `/report`: خلاصهٔ معاملات فرضی و وضعیت.
- `/pause`: توقف هشدار و ورود فرضی جدید؛ معاملهٔ فرضی باز تا خروج پیگیری می‌شود.
- `/resume`: ادامهٔ پایش آزمایشی.
- `/help`: راهنما.
- فرمان‌ها فقط از `TELEGRAM_CHAT_ID` پذیرفته می‌شوند؛ در گروه، شناسهٔ کاربر اپراتور نیز باید در `TELEGRAM_OPERATOR_USER_ID` تعیین شود. یک مقصد/اپراتور، یک فرایند و یک مصرف‌کنندهٔ `getUpdates` برای هر توکن در نظر گرفته شده است.
- Bot API polling با webhook هم‌زمان سازگار نیست؛ اگر قبلاً روی همین توکن webhook تنظیم کرده‌اید، ابتدا با ابزار رسمی آن را حذف کنید. این پروژه تنظیم قبلی شما را خودکار تغییر نمی‌دهد.
- فقط تأیید فنی تازه به صورت خودکار ارسال می‌شود. وضعیت‌های انتظار و ردشدن در ژورنال ذخیره می‌شوند. پیام علت، ابطال، هدف فرضی، وضعیت خبر، نسخه و منبع دارد؛ «تأیید فنی» به معنی تأیید خبر یا دستور معامله نیست.
- صف ارسال روی SQLite پایدار است؛ ارسال ناموفق تا شش بار با فاصله تکرار می‌شود و بعد از یک کندل منقضی می‌شود. ارسال دقیقاً یک‌بار در شبکه قابل تضمین نیست: اگر تلگرام پیام را بپذیرد اما پاسخ گم شود، تکرار ممکن است. شناسه/زمان یکسان قابل تشخیص است.

## قواعد عددی آزمایشی

قواعد در `watchbot/core.py` مستقل از مدل زبانی محاسبه می‌شوند. قیمت‌ها و چارت از OHLCV به دست می‌آیند؛ LLM یا مدل تصویر، قیمت و هندسه تولید نمی‌کند.

۱. حداقل ۲۰۰ کندل بسته‌شده در هر تایم‌فریم؛ EMA50 از ابتدای ورودی با `adjust=False` آغاز می‌شود. تغییر طول تاریخچه می‌تواند EMA را کمی تغییر دهد؛ در مقایسه‌ها یک طول ثابت نگه دارید.

۲. فیلتر روزانهٔ لانگ: قیمت بالاتر از EMA50 و تنکان بالاتر از کیجون؛ شورت برعکس. حالت مختلط بدون ستاپ است.

۳. فیلتر ۴ساعتهٔ لانگ: قیمت بالاتر از EMA50 و بالای ابر فعلی و تنکان بالاتر از کیجون؛ شورت برعکس. ابر فعلی از Spanهای محاسبه‌شده در ۲۶ کندل قبل استفاده می‌کند. چیکو به عنوان فیلتر استفاده نشده است.

۴. در پنج کندل قبلی ۵دقیقه، لانگ باید لمس EMA50 یا فاصلهٔ حداکثر ۰٫۲ ATR بالای آن داشته باشد؛ سپس کندل فعلی صعودی، بالای EMA و بالای سقف سه کندل قبل بسته شود. شورت متقارن است. ATR در این نسخه میانگین سادهٔ TR چهارده کندل است، نه فرمول Wilder.

۵. ابطال لانگ زیر کمترین کفِ کندل تأیید و پنج کندل قبلی، با حاشیهٔ ۰٫۱ ATR؛ شورت بالای بالاترین سقف. فاصلهٔ ابطال باید بین ۰٫۱ تا ۳ درصد باشد. هدف اولیه دو برابر فاصلهٔ ابطال است. این اعداد **فرضیهٔ آزمایشی‌اند**، نه پارامتر بهینه یا اثبات‌شده.

۶. انقضای هشدار یک کندل و فاصلهٔ هشدارهای متوالی هر نماد حداقل شش کندل است. مدل paper نیز فقط یک ستاپ در انتظار یا یک معامله در کل نمادها دارد.

الگوهای جزوه و بستهٔ KX در این نسخه به عنوان کتابخانهٔ اجرایی وارد نشده‌اند. این کد یک استراتژی عددی مستقل و قابل آزمون است؛ اسامی الگوها و امتیاز ساختاری را به احتمال برد تبدیل نمی‌کند.

## خبر و فاندامنتال: وضعیت واقعی نسخهٔ اول

**جمع‌آوری خودکار خبر هنوز پیاده‌سازی نشده است.** فایل `news.json` یک بازبینی دستی با منابع مشخص و مهلت حداکثر شش ساعت است. فایل پیش‌فرض UNKNOWN است. هشدار فنی با برچسب خبر نامشخص ممکن است ارسال شود، اما ورود فرضی با خبر UNKNOWN/BLOCKED مجاز نیست.

ساختار بازبینی دستی:

```json
{
  "reviewed_at": "2026-10-20T12:00:00Z",
  "valid_until": "2026-10-20T14:00:00Z",
  "sources": ["https://www.federalreserve.gov/monetarypolicy/fomccalendars.htm"],
  "blocked_symbols": [],
  "events": [{
    "name": "نام رویداد واقعاً بررسی‌شده",
    "start": "2026-10-20T12:30:00Z",
    "end": "2026-10-20T13:30:00Z",
    "symbols": ["*"]
  }]
}
```

تاریخ‌های بالا **نمونهٔ ساختار** هستند؛ ادعای وقوع رویداد در آن ساعت نیستند. لینک به تنهایی اثبات بررسی نیست؛ اپراتور باید واقعاً تقویم و خبر را بررسی کند و زمان‌ها را ثبت کند. رویداد ناگهانی، تأخیر منبع و اخبار پروژه ممکن است پوشش داده نشوند.

## معاملات فرضی

پیش‌فرض `paper_enabled: false` است تا بدون انتخاب آگاهانهٔ فرض‌های هزینه، آمار گمراه‌کننده تولید نشود. برای آزمایش مستقل:

۱. از `config.json` کپی مثلاً `paper.json` بسازید.

۲. در کپی، `paper_enabled` را `true` و `database` را `runtime/paper-01.sqlite3` قرار دهید؛ بازبینی معتبر خبر نیز لازم است.

۳. هزینه‌ها را برای آزمایشتان تنظیم کنید و سپس:

```bash
python -m watchbot --config paper.json run
python -m watchbot --config paper.json status
python -m watchbot --config paper.json export --output runtime/paper-export
```

فرض‌های اولیه صرفاً مثال‌اند: سرمایهٔ فرضی ۱۵۲٫۳۷ USDT، ریسک هر معامله ۰٫۲۵٪، توقف پس از زیان تجمیعی روزانهٔ ۰٫۷۵٪ یا دو ضرر متوالی همان روز، کارمزد هر طرف ۵ bps، لغزش هر طرف ۲ bps و ذخیرهٔ هزینهٔ فاندینگ ۳ bps به ازای ۸ ساعت. ۱ bp معادل ۰٫۰۱٪ است. اینها تعرفهٔ واقعی هیچ صرافی نیستند.

- اندازهٔ معامله با فاصلهٔ ابطال، کارمزد، لغزش و ذخیرهٔ فاندینگ محاسبه می‌شود. سقف ارزش اسمی پیش‌فرض فقط ۱ برابر سرمایه است؛ این نسخه مدل معامله با اهرم ۱۵ یا ۲۰ نیست.
- ورود فرضی در بازشدن کندل بعدی محاسبه می‌شود، وقتی دادهٔ آن کندل بسته و دریافت شد؛ پیام به معنی پرشدن سفارش زنده نیست. اگر گپ ورود بیش از ۰٫۳٪ باشد، لغو می‌شود.
- اگر هدف و حد ابطال در یک کندل لمس شوند، حد ابطال مقدم فرض می‌شود. گپ از روی حد ابطال با قیمت بدتر بازشدن محاسبه می‌شود؛ در نتیجه زیان می‌تواند بیشتر از بودجهٔ برنامه‌ریزی‌شده باشد.
- خروج زمانی پس از ۴۸ کندل (چهار ساعت) است. کارمزد و لغزش دو طرف و فاندینگ تخمینی از نتیجه کسر می‌شوند؛ دریافت فاندینگ مثبت مدل نمی‌شود.
- روز ریسک با نیمه‌شب تهران عوض می‌شود. سود روزانه زیان‌های قبلی همان روز را از سقف «زیان تجمیعی» پاک نمی‌کند.
- افت سرمایهٔ گزارش‌شده فقط روی موجودی پس از معاملات بسته‌شده است؛ افت لحظه‌ای، لیکوییدیشن Mark Price، عمق دفتر سفارش، اندازه/گام سفارش، نگهداری مارجین و جهش هزینه‌ها مدل نشده‌اند.
- SQLite وضعیت را پس از راه‌اندازی مجدد نگه می‌دارد. پارامترهای متفاوت باید دیتابیس آزمایش متفاوت داشته باشند؛ تغییر تنظیمات در دیتابیس قبلی رد می‌شود.

## بازپخش دادهٔ واقعی خودتان

برای هر نماد سه فایل با نام دقیق `SOLUSDT_5m.csv`، `SOLUSDT_4h.csv`، `SOLUSDT_1d.csv` و مشابه برای سایر نمادهای تنظیمات آماده کنید:

```csv
open_time,open,high,low,close,volume,close_time
1792497600000,100,101,99,100.5,1000,1792497899999
```

زمان‌ها integer milliseconds UTC هستند. `close_time = open_time + interval_ms - 1`. هر فایل حداقل ۲۰۰ کندل پیوستهٔ معتبر لازم دارد. تایم‌فریم‌های بالاتر باید دورهٔ بازپخش را با تاریخچهٔ کافی بپوشانند؛ دادهٔ ناقص اجازهٔ ستاپ ندارد. نمادها و `source` باید با دادهٔ واقعی شما منطبق باشند؛ برای CSV از نام روشن منبع استفاده کنید.

```bash
python -m watchbot --config paper.json replay --data ./my-csv
```

بازپخش با قواعد خبر پیش‌فرض معاملات ثبت نمی‌کند، مگر بازبینی تاریخی معتبر داشته باشد. برای بررسی **صرفاً فنی** می‌توانید آگاهانه خبر را کنار بگذارید:

```bash
python -m watchbot --config paper.json replay --data ./my-csv --ignore-news-for-research
```

این گزینه فقط در replay وجود دارد و تمام نتایج را `UNSCREENED_RESEARCH` علامت می‌زند؛ نباید آن را نتیجهٔ استراتژی دارای فیلتر فاندامنتال معرفی کنید. نتایج در `runtime/export/` کنار پوشهٔ charts ذخیره می‌شوند. هر replay باید دیتابیس تازه داشته باشد. معاملات بازِ انتهای داده جدا گزارش می‌شوند و به زور با سود/ضرر دلخواه بسته نمی‌شوند.

چند روز تست برای یافتن باگ مفید است؛ برای نتیجه‌گیری دربارهٔ سودآوری کافی نیست. دورهٔ خارج از نمونه، وضعیت‌های صعودی/نزولی/رنج، تعداد معاملات، هزینه‌های واقع‌بینانه و حساسیت به پارامترها باید جدا بررسی شوند.

```bash
docker compose down
```

حالت اجرا کاربر غیر root، فایل‌سیستم فقط‌خواندنی و حجم پایدار `bot-state` دارد. پاک‌کردن volume ژورنال را حذف می‌کند. برای تغییر مجموعهٔ قواعد، تنظیمات را با نام دیتابیس جدید عوض کنید؛ پارامترها در زمان اجرا خودکار بارگذاری نمی‌شوند، اما فایل news در هر تحلیل دوباره خوانده می‌شود.

## انتقال به GitHub

هیچ توکن، `.env` یا دیتابیس را وارد مخزن نکنید. یک مخزن شخصی خالی بسازید، سپس از پوشهٔ پروژه:

```bash
git init -b main
git add .
git commit -m "Add paper-only multi-timeframe crypto research bot"
git remote add origin https://github.com/YOUR_ACCOUNT/crypto-watchbot.git
git push -u origin main
```

CI فقط تست و دمو را اجرا می‌کند؛ برای اجرای دائمی طراحی نشده و به توکن تلگرام نیاز ندارد. این بسته شامل استقرار فعال یا حساب میزبانی نیست.
